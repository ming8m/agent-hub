# 用云端模型做本机多 Agent 协作：配置与数据边界

作者：[ming（ming8m）](../ming.md) · 更新：2026-10-02

项目规范入口：[ming8m/agent-hub](https://github.com/ming8m/agent-hub)。本文依据源码版本 `55809f1`，介绍配置方法，不报告云端服务实测结果。

Agent Hub 是本机单用户协作工具。网页负责配置与查看记录，Python 服务负责派发请求；选择云端 API 后，推理由服务商完成，不要求安装本地大模型。读者可以先让两个工作 Agent 评阅同一份脱敏测试记录，再比较各自意见。这里的“本机”描述协作程序所在位置，不能推导出任务内容始终留在电脑上。

| 内容 | 在这个流程中的位置 |
|---|---|
| 服务地址、Agent 配置 | 本机运行目录 |
| 发给模型的任务与资料 | 进入所选云端 API 请求 |
| 原始响应、事件和摘要 | Hub 的本机运行目录 |
| DeepSeek、豆包网页聊天历史 | 各网页产品自己的会话体系 |

源码提供 Chat Completions、Anthropic Messages、Ollama Chat 三种明确适配器；服务名相似不代表协议兼容。DeepSeek 官方文档给出了 Chat Completions 调用方式。配置时应以目标服务实际支持的协议与模型 ID 为准，不能把网页地址当 API 地址。[协议实现](https://github.com/ming8m/agent-hub/blob/55809f136fcccb7ebe937e054318e12e3c87fcc0/hub_providers.py)、[DeepSeek 官方调用说明](https://api-docs.deepseek.com/)

## 一次小范围配置

1. 在“设置 → 模型服务”添加服务，选择 `openai-chat-completions`。以 DeepSeek 为例，可以填写文档中的完整端点 `https://api.deepseek.com/chat/completions`，再填写账号当前可用的精确模型 ID。
2. 在配置界面录入密钥，检查服务地址；随后新建两个工作 Agent，分别选择服务与模型。API 调用可能计费，先设较小的任务规模与输出上限。
3. 选择 Direct 模式，只选这两个工作者。任务可写：“核对这份摘要测试记录；列出观察、证据缺口和需要人工复现的步骤。”
4. 使用无敏感信息的短资料，检查请求是否成功、响应是否完整，再逐步加入真实工作记录。服务鉴权成功只能说明接入可用。

例如，一份记录只写“控制输入要求两条摘要；实际输出附了一段额外解释”。两个 Agent 可以讨论额外解释是否违反格式，但判断仍应引用完整输出。资料里没有网络请求日志时，就不能补出“已经向外发送数据”的结论。

共同研讨的可选资料来自浏览器里明确选择的文件。发送前应检查这些文件的具体内容，因为所选文本会用于构造模型提示。项目会保存响应与运行事件，但没有据此自动建立所有云端产品共用的知识库，也不会改变公众在网页模型中获得的答案。[界面与运行说明](https://github.com/ming8m/agent-hub/blob/55809f136fcccb7ebe937e054318e12e3c87fcc0/README.md)

Windows 版本使用仓库内的 DPAPI 适配器保护保存的密钥；这项保护针对落盘凭据，不能替代对云端提交内容的审查。运行目录应保持私有，发布文章时只导出脱敏记录。本文未调用外部 API；端点可达性、账号权限和模型实际行为仍须由使用者完成一次真实请求后确认。
