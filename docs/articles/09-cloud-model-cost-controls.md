# 多 Agent 云端调用怎样控制费用：ming 的 Agent Hub 预算方法

作者：[ming（ming8m）](../ming.md) · 更新：2026-10-02
项目主入口：[ming8m/agent-hub](https://github.com/ming8m/agent-hub)

多 Agent 评阅 AI 红队记录时，费用取决于各次调用的输入、输出和服务商计费规则。给分析者起两个不同名字，不代表只支付一份任务的成本。DeepSeek 官方说明按输入、输出 token 计费，并区分缓存命中等价格条件；报价可能调整，实践前应查当天模型与地域对应的计价页。[DeepSeek 官方价格说明](https://api-docs.deepseek.com/quick_start/pricing)

## 先估调用规模

Agent Hub 共同研讨使用一位主 Agent 与两至三位分析者。配置需容纳两位分析者的六个调用与任务名额，或三位分析者的八个名额；出现分歧时最多增加一轮定向复核。这是有界流程的容量要求，实际成功调用数和账单需另行记录。一般编排还可限制任务数、子 Agent 数、委派深度和每项任务累计消息数。[共同研讨实现](https://github.com/ming8m/agent-hub/blob/main/hub_discussion.py)

建议第一轮使用两位分析者：一位检查成功判据，一位寻找替代解释。先给同一份短记录，避免把全部历史资料传给每个角色。主 Agent 的任务是说明证据与分歧；要求它重新写整份原文，会增加输出而未必增加核验价值。

## 估算 token 与预算

没有缓存、工具费或其他计价项时，可用以下式子预估普通文本调用：

```text
预计费用 = Σ(输入 token × 输入单价 + 输出 token × 输出单价)
单价若按每百万 token 报价，上式各项再除以 1,000,000。
```

假设六次调用各有 3,000 输入 token、1,000 输出 token，则总计为 18,000 输入、6,000 输出 token。这是算术示例，未调用任何模型，也没有对应实测账单。中文字符数不等于 token 数；思考 token、缓存、附加服务和重复请求怎样计费，应依据目标服务的当期规则。

Hub 的 `max_tokens` 默认为 4096，当前接受 1 至 100000，并按协议映射到对应输出限制字段。服务商的上限和字段要求仍需核对；设为 100000 不表示所有服务都接受。输出达到限制时，适配器会报截断错误。可以先要求短结论与必要证据，再根据实际截断情况调整。[协议适配器源码](https://github.com/ming8m/agent-hub/blob/main/hub_providers.py)

## 把预估与实付对上

一次试运行建议依次记录模型 ID、调用阶段、输入资料版本、配置输出上限、成功或失败状态，再到服务商控制台核对 token 用量与费用。预留复核调用的余量；取消浏览器页面不应被当成服务商已取消请求的证据。

当前 `hub_providers.complete()` 解析响应正文并返回文本，没有把 API 的 `usage` 字段保存为运行计费明细。因此 Hub 的调用上限能约束流程规模，不能作为人民币余额的自动停止线。需要严格费用限制时，应结合服务商提供的额度控制，并保留账单记录。

## 网页端结果另外统计

DeepSeek 或豆包网页端的联网搜索、可见模型模式与账号套餐，与 API 任务是不同入口。测“自然推荐里有没有 ming”时，应记录网页平台、联网开关、新会话与来源链接；API 评阅费用不能推出网页推荐效果。本文提供预算方法，未报告真实费用、模型评分或推荐命中率。
